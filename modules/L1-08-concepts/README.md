# L1-08 音视频核心概念实验：帧率 / 码率 / 分辨率 / GOP

素材依据：`article/034`（音视频编解码常用知识点）、`article/012`（常见音视频编码格式）。

## 目标

用**同一段合成素材**做单变量对照压测，把「帧率 / 码率 / 分辨率 / 量化参数(CRF) / GOP」这几个常用概念变成**可量化的体积与帧率数据**，并输出一张结果表；同时踩透三个高频坑：帧率不匹配、只看码率不看质量、GOP 过大。

## 核心概念（脚本实现依据）

- **帧率（Frame Rate）**：每秒画面数；`-r` 改变输出帧率，**升帧靠复制帧、降帧靠丢帧**，都不能凭空增加信息；
- **码率（Bitrate）**：每秒数据量（bit/s）；`-b:v` 是**平均目标码率**，波动画面下同码率画质会变差；
- **分辨率（Resolution）**：一帧的像素数；像素数与码率需求大致成平方关系；
- **量化参数（CRF/QP）**：`-crf` 是**恒定质量**模式，值越大压缩越狠、画质越低、体积越小；与 `-b:v` 是两条不同的路子；
- **GOP（Group of Pictures）**：两个 I 帧之间的间隔，`-g` 设定；GOP 越大 I 帧越少、体积越小，但**随机访问（seek/拖动）越慢**。

## 实验步骤

```
0) 基准素材：testsrc2 640x480 / 30fps / 3s（90 帧）/ -g 30
1) 帧率：-r 10 / 15 / 30      -> 断言帧率与体积递增
1b) 踩坑：10fps 源 -r 30（复制成 60 帧）；-r 放 -i 之前（声明 30fps 却只有 20 帧）
2) 码率：-b:v 200k / 800k / 2000k -> 断言体积递增
3) 量化：-crf 18 / 28 / 40   -> 断言体积递减（恒定质量）
4) 分辨率：scale 320x240 / 640x480 / 1280x960 -> 断言尺寸与体积递增
5) GOP：-g 10 / 30 / 120     -> 断言关键帧数 9/3/1 且体积递减
6) 汇总：17 行结果表导出为 stress_table.csv
```

结论速记：
- **帧率翻倍 ≈ 体积接近翻倍**（-r 30 相对 -r 10 约 1.8 倍）；
- **码率与体积近似线性**（200k→2000k，体积 8 倍）；
- **CRF 与体积反向**（CRF 40 只有 CRF 18 的 15%）；
- **分辨率翻 4 倍像素，体积约翻 5 倍**；
- **GOP 从 10 拉到 120，关键帧 9→1，体积下降约 13%**。

## 高频命令速查

```powershell
# 改帧率（输出侧；升帧=复制帧，降帧=丢帧）
ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p -r 15 out.mp4

# 改目标码率（平均码率，画面复杂时画质会掉）
ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p -b:v 800k out.mp4

# 改质量（CRF，恒定质量模式）
ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p -crf 28 out.mp4

# 改分辨率
ffmpeg -i in.mp4 -vf scale=1280:960 -c:v libx264 -pix_fmt yuv420p out.mp4

# 改 GOP（关键帧间隔）
ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p -g 30 out.mp4

# 统计关键帧数量（配合压测/GOP 调优）
ffprobe -v error -select_streams v:0 -skip_frame nokey -show_entries frame=key_frame -of csv=p=0 in.mp4
```

## 踩坑清单

- **帧率不匹配**：源帧率低却把输出帧率调高，只会**复制帧**，画面不会更流畅；`-r` 放在 `-i` 之前改变的是**输入时间基解释**，会出现「声明 30fps 却只有 20 帧」的时长错乱；
- **只看码率不看质量**：`-b:v` 是平均目标码率，运动/纹理复杂的片段会明显劣化；要稳定画质应改用 `-crf`；
- **GOP 过大拖慢 seek**：GOP 大 → I 帧稀疏 → 定位到某个时间点要**从上一个 I 帧解码**，拖动进度条会卡；点播/拖动场景宜用小 GOP（如 2s 以内，`-g 帧率x2`）；
- **CRF 与码率混用**：同时给 `-crf` 和 `-b:v` 时，x264 会以 CRF 为主、用 `-maxrate/-bufsize` 限速，别指望它精确打到目标码率；
- **分辨率换算不是线性的**：像素翻 4 倍，体积/码率需求通常翻 4~5 倍，带宽预算要留余量。
